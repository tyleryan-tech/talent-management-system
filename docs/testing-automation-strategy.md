# 测试自动化方案

本文档定义人才管理系统的测试方案和开发收尾自动化。目标不是只证明“功能能点”，而是同时覆盖用户视角的可用、好用、可信，以及技术视角的长期可维护、可扩展、可观测。

## 测试目标

用户视角：

- 关键角色 HRBP、汇报经理、产品线负责人、超级管理员看到的数据范围一致且可理解。
- 高频任务路径顺畅，包括登录、切换产品线、查看花名册、绩效流转、组织审批、导入导出、AI 分析入口。
- 终端提示使用中文；敏感或技术细节不直接暴露给普通用户。
- 表格、筛选、状态标签、错误恢复和空态能支撑约 1 万名员工规模下的日常操作。

技术视角：

- `employees` 员工主数据保持单一事实来源。
- 页面可见性、store computed/API 裁剪、服务端写入校验一致。
- 产品线数据按 `tm_L{lineId}_*` 隔离，全局用户数据不被产品线操作污染。
- 产品线、角色、周期切换前同步落盘，避免 debounce 或异步残留造成跨上下文污染。
- Node/Vercel API、Go 兼容后端、Vite/TypeScript 结构保持可演进。

## 分层测试

| 层级 | 自动化入口 | 覆盖目标 | 门禁级别 |
| --- | --- | --- | --- |
| 前端 store/业务逻辑 | `tests/index.html` / `npm run test:browser` | 员工、组织、绩效、同步、产品线、视图 computed | 必跑 |
| 浏览器真实环境 | `scripts/run-browser-tests.mjs` | DOM、localStorage、IndexedDB、CDN 脚本加载、控制台错误 | 必跑 |
| Node API 冒烟 | `npm run test:server` | health、登录、鉴权、产品线、经理整表写拒绝 | 必跑 |
| Vite/TS 构建 | `npm run build:vite` | `src/` 结构类型与构建健康度 | 必跑，但不代表主线完整测试 |
| Go 兼容后端 | `go test ./...` | Go 备选后端的认证、scope、路由兼容 | 环境可用时必跑，否则报告跳过 |
| CI 回归 | `.github/workflows/test-automation.yml` | PR/push 自动验证和报告留存 | 必跑 |

## 风险驱动覆盖

高风险业务改动必须先出方案、确认人工待定项，再开发并补测试：

- 薪酬、Offer、候选人评价、员工状态。
- 考勤、离职、调动、晋升。
- 绩效周期、审批、校准、归档、申诉。
- 组织变更审批。
- 产品线切换、服务端 workspace scope、patch 合并和版本冲突。

每类改动的最低测试要求：

- 正向用例：目标角色按预期完成任务。
- 边界用例：无权限、脏数据、缺字段、重复主键、无效外键、版本冲突或审批未通过。
- 一致性用例：UI 可见范围、store 过滤、API 读裁剪、写入校验结果一致。
- 回归用例：修复 bug 时把复现场景固化到最匹配的 `tests/*.js` 或 API 测试中。

## 自动化收尾

每次开发任务结束执行：

```bash
npm run verify:dev:self-heal
```

该命令会：

1. 运行主线浏览器测试，并生成 `test-reports/browser-tests-latest.md/json`。
2. 运行 Node API 冒烟测试。
3. 运行 Vite/TypeScript 构建检查。
4. 检测 Go 环境，存在时运行 `go test ./...`，不存在时在报告中标记 skipped。
5. 汇总生成 `test-reports/dev-check-latest.md/json`。
6. 失败时最多 3 轮自动处理确定性问题，例如安装缺失 npm 依赖、安装 Playwright Chromium 浏览器，再复跑。

业务逻辑失败不能靠脚本猜测修复。此时 Codex/开发者应读取报告中的失败用例和日志，只修复根因，复跑失败测试；连续 3 轮仍失败则停止并报告剩余风险。

## 报告标准

报告必须包含：

- 运行时间、耗时、Node/平台信息。
- 每个检查项的 passed/failed/skipped 状态。
- 浏览器测试的 passed/failed/skipped 数。
- 失败 suite、test、错误消息。
- 控制台错误、页面异常、请求失败。
- 自动修复动作和复跑轮次。

报告默认不提交到仓库；CI 会把报告作为 artifact 留存。

## 长期演进

后续建议按优先级补齐：

- 增加真实 app 路由级 Playwright E2E：登录、角色切换、花名册、绩效审批、产品线切换。
- 引入可访问性和可用性自动检查：焦点顺序、按钮可点区域、表单错误提示、关键页面无控制台错误。
- 增加服务端集成测试：Vercel body 兼容、409 冲突恢复、经理越权 patch 拒绝。
- 增加导入链路测试：字段映射、缺失必填列、重复主键、替换/追加策略。
- 增加性能基准：1 万员工 seed、关键 computed 耗时、产品线切换耗时、API snapshot 大小。
- 增加审计和安全测试：敏感字段裁剪、AI 分析 SQL 安全边界、候选人/Offer 权限隔离。
