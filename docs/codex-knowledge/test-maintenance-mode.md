# Test Maintenance Mode

本项目默认开启测试自动维护模式。它的含义是：每次开发任务不仅要跑现有自动化测试，还要让测试集跟随功能变化一起演进。

## 默认工作流

1. 读 `AGENTS.md` 和 `docs/codex-knowledge/testing-rules.md`。
2. 判断本次改动是否会改变运行行为、业务规则、权限范围、数据结构、API、持久化或用户交互。
3. 会改变行为时，先定位最匹配的测试文件。
4. 编码时同步补测试，而不是最后再临时补。
5. 新增功能至少补正向和边界/异常用例。
6. 修复 bug 必须补回归用例。
7. 高风险业务改动必须覆盖角色权限、产品线隔离、主数据一致性和审批/状态约束。
8. 运行 `npm run verify:dev:self-heal`。
9. 最终回复说明新增/更新的测试和最新报告结果。

## 不补测试的允许条件

仅以下场景可以不新增或更新测试：

- 纯文档更新。
- 注释或命名调整，且运行行为不变。
- 纯样式微调，且没有交互、可见性、权限或布局风险。
- 测试基础设施本身调整，并且已有验证覆盖其效果。

即使不补测试，也必须在最终回复中说明原因。

## 自动修复边界

`npm run verify:dev:self-heal` 只能自动处理确定性环境问题，例如缺少 npm 依赖、Playwright 浏览器、Go module 校验文件。业务断言失败、权限错误、数据污染、审批流错误、构建类型错误必须由 Codex/开发者修复根因。
